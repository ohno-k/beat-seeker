# 前作ランキングの更新（切り替え後に取り込まれた前作 CSV の反映）

ランキングページの作品セレクトで前作（33 Sparkle Shower）を選ぶと出る「終了時点」のランキングは、
世代切替（2026-09-16 07:00 JST）に撮った `version_pt_snapshots` が元データになっている。
その後も「前作の最後のプレー分をまだ取り込んでいなかった」利用者が前作の CSV を歴代スコア（`past_scores`）として
入れてくるため、取り込みのたびに本人の前作 PT を計算し直してスナップショットへ反映する仕組みを 2026-09-16 に入れた。
表示のラベル「Sparkle Shower 終了時点」はそのまま（利用者の判断）。

## 仕組み

| 部品 | 役割 |
|---|---|
| `service/ArchivedVersionPtService` | `past_scores(version)` から BEAT / RATE / KENBAN / SARA の 4 指標を計算し、`version_pt_snapshots` の本人行を更新（無ければ新規作成）。順位列（beat_rank / rate_rank）の振り直しと `PreviousVersionPtService` のキャッシュ破棄も担当 |
| `controller/PastScoreController#uploadPastScores` | 取り込みで 1 件でも追加・更新があり、その作品にアーカイブ（スナップショット）があれば、同じトランザクション内で上を呼ぶ。応答に `archivedPt`（before/after）を載せ、フロントの結果モーダルに「{作品} ランキング BEAT-PT: 15,126.9 → 15,164.3」の行と説明文を出す。失敗しても取り込みは成功として返す |
| `service/VersionTransitionService#freezeDifficultyTable` | 世代切替時に公開中の難易度表を revision `archive:<前作>` として凍結する（スケジューラの手順 `freeze-difficulty`、snapshot の直後。既にあれば何もしない） |
| `ScoreRecalculationService#calculatePtTotals` / `loadInformalRanks(revision)` | 4 指標をまとめて出す共通ロジックと、任意 revision の難易度表読み込み |
| `POST /api/admin/version-transition/refresh-archived-pt` | 管理用の一括再計算。`version`（既定: 現行作−1）、`since`（省略時は「複製より後」= その作品の最古の imported_at + 1 秒）、`userId`、`dryRun`（既定 true） |

## 難易度表は「切り替え時点の表」で計算する

新作初日 07:24 に難易度表の大改訂（第6版、918 曲変更）を適用したため、現行の active で前作 PT を計算すると
スナップショット（旧表で計算）と物差しが変わる。凍結表 `archive:33` で計算すると、追加取り込みの無い人は
スナップショットと同じ値が再現できる。

- 2026-09-16 の検証（本番、読み取りのみ）: スナップショットがあり切替後の取り込みが無い 56 人のうち **54 人が 4 指標とも完全一致**。
  残り 2 人は past_scores が 0 行（INFINITAS 由来の記録だけの人）。active で計算した場合は 0 人しか一致しない。
- `archive:33` は切替時に自動では作られなかった（仕組み自体が同日実装）ので、active に第6版の差分（`difficulty_revisions.changed_json`）を
  逆適用して復元し、上の検証を同じトランザクション内で通してから commit した。次回作からは `freeze-difficulty` の手順が自動で作る。
- `archive:` 接頭辞は管理画面のプロファイル一覧（`profile:` 接頭辞）に出ないので、画面操作で消えない。
- 凍結表が無い作品は active で代用する（警告ログ）。

## 更新の規則

- 指標ごとに **上回ったときだけ** 書き換える。`past_scores` はアーケードの記録だけなので、INFINITAS 込みで撮った
  スナップショットより低く出ることがあり、取り込みで到達点が下がるのを避けるため。
- スナップショットが無い人（切替後に登録した新規ユーザー）は行を新規作成する。
- 過去作スコアの削除（`DELETE /api/scores/past/{version}`）ではスナップショットを消さない（終了時点の記録として残す）。
- `last_uploaded_at` は更新時に現在時刻へ進める（ランキングの「最終更新」に出る）。

## 2026-09-16 の追いつき

デプロイ前に取り込まれていた分は、`ArchivedVersionPtService#refreshUploadedSince(33)` をローカルから本番 DB に対して実行して反映した
（一時テスト `ArchivedPtRefreshProdRunner`、実行後に削除。バックアップは当日の scratchpad `backup_version_pt_snapshots_33_*.tsv`）。
結果（2026-09-16 16:46 JST 実行）: 対象 46 人（複製より後に 33 を取り込んだ人）のうち **更新 22 人・新規作成 9 人・変更なし 15 人**。
変更なしは「切替前と同じ最終 CSV を入れ直した」人（再計算がスナップショットと一致）。最大の変化は Neguro（BEAT 6,285.5 → 8,006.5）。
