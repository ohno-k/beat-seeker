## 1. システム概要

### 1.1 目的
beatmania IIDX プレイヤー向けに、スコアデータを一元管理し、独自の指標（BEAT-Tier / Rate-Tier）でスキルを可視化する Web アプリケーション。公式サイト (eagate) から取得した CSV・ARENA バトルデータを取り込み、ランキング・難易度表投票・フレンド機能・譜面傾向分析・スコア予測などを提供する。

### 1.2 提供価値
- **自身の総合実力の可視化**：独自の BEAT-PT / Rate-PT / Precision-PT を算出しティア（Legend〜Beginner）を付与
- **他プレイヤーとの比較**：フレンド・全ユーザーランキング、曲別ランキング、ARENA 戦績
- **コミュニティ機能**：難易度表投票・コメント、オプション投票、アクティビティフィード
- **成長支援**：スコア予測、スキルツリー、譜面傾向分析、ランクアップアドバイス

### 1.3 想定利用者
- beatmania IIDX プレイヤー（カジュアル〜皆伝）
- 管理者（特定 User ID=18 のみ、楽曲・難易度表のドラフト編集とポイント再計算が可能）

### 3.2 業務フロー（主要）

#### (A) スコアアップロード
1. ユーザーが eagate 経由でブックマークレットを実行 or CSV をダウンロード
2. フロントエンドが `#data=<base64>` URL フラグメント or ドロップゾーンから CSV 受領
3. `csvParser.ts` が Shift_JIS をデコードし `ScoreData[]` 化
4. `useScoreUpload.upload()` が `POST /api/scores/upload` へフラット化 JSON を送信
5. バックエンドは既存スコアと比較し、改善分のみ UPSERT
6. フロントエンドが BEAT-PT / Rate-PT を再計算し、差分モーダルを表示
7. `POST /api/scores/save-history-log` で履歴ログを保存（ティア遷移があれば ActivityLog 発行 → フレンドに Web Push）

#### (B) フレンド申請 〜 スコア被抜き通知
1. ユーザーが `FriendSearchModal` でユーザー検索 → 申請送信
2. 受信側の `NotificationBox` に通知、承認で双方向 Friendship 作成
3. 自分のスコア更新時、過去の自分 < フレンドスコア かつ 更新後 > フレンドスコア なら `SCORE_BEAT` 通知
4. 受信側が `pushSubscription` 登録済みなら Web Push 送信

#### (C) ゲームデータ更新（管理者）
1. 管理者が `AdminGameDataModal` で曲データ／難易度表をドラフト編集
2. `POST /api/admin/game-data/apply` で `revision='active'` に適用
3. `ScoreRecalculationService.recalculateAllUsersAsync` が全ユーザーの BEAT-PT / Rate-PT を非同期再計算
4. `SongRankBatchService` が曲別順位キャッシュを更新

## 8. BEAT-Tier / Rate-Tier ビジネスロジック（概要）

### 8.1 BEAT-PT
- 各譜面について `scoreRate = score / (notes * 2)` を求め、`(rate/100)^1.3 × weight` に 77.77%/88.88%/94.44% 通過でボーナスを加算
- ウェイトは難易度（☆11.0 → 150pt、以後 0.1 刻みで +2pt、☆12.5 以降は +3pt）
- 上位 100 曲の合計を総 BEAT-PT とし、52 階層（Legend 〜 Beginner）のティアに分類

### 8.2 Rate-PT
- スコアレート 97%+ などの高精度帯を対象に、倍増系列（25600 / 12800 / ...）のしきい値でティア判定
- `showRateTier` フラグで表示 ON/OFF

### 8.3 Precision-PT
- 精度 (PGREAT 率) を別指標で集計してランキング化

### 8.4 再計算タイミング
- 楽曲マスタ／難易度表適用時（管理者）
- スコアアップロード時（差分のみ）
- 管理者の明示的トリガー (`/api/admin/recalculate-points`)

### 9.2 本番デプロイ
- Docker Compose でフロント（nginx）・バック（Spring Boot）・DB（Postgres）を起動
- 環境変数: `FRONTEND_URL, JWT_SECRET, DB_*, GMAIL_*, VAPID_*, KOFI_VERIFICATION_TOKEN`
- フロントは `npm run build` → `dist/` を nginx から配信

### 9.3 保守
- `DataInitializer` が起動時に `language/showRateTier` のデフォルト補完と、`song_data.json / difficulty_table.json` のシードを行う
- 管理者はドラフトで楽曲／難易度表を編集し、`apply` で本番反映＋ポイント再計算

## 10. 用語定義

| 用語 | 定義 |
|------|------|
| BEAT-PT | 当サイト独自のスキル点数。上位 100 曲の点数合計 |
| Rate-PT | 高精度プレイ評価値。倍増系列のしきい値でティア判定 |
| Precision-PT | 精度 (PGREAT 率) 指標 |
| informalRank | 非公式難易度表でのランク（例：12.5、Uncategorized） |
| Textage | IIDX 譜面表示サービス。プロファイルキーとして URL フラグメントを保管 |
| DJ LEVEL | IIDX の公式評価（AAA/AA/A/B/C/D/E/F） |
| ARENA | IIDX の対戦モード |
| BS-xxxxxxxx | サポーター認証用トークン形式（Ko-fi メッセージに記入） |
| revision | ゲームデータの状態（`active` = 公開中 / `draft` = 編集中） |
