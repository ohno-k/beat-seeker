# 前作データ取り込みガード

作品切替後に、前作（例: 33 Sparkle Shower）のスコアを現行作（34 ZINRAI）として取り込んでしまう事故を止める仕組み。
2026-09-16（ZINRAI 稼働初日）に 3 人がこの状態になり（前作ページで実行したブックマークレット 1 件、切替前にダウンロードした
前作 CSV 2 件）、手作業で past_scores へ移した経緯から同日に導入した。

## なぜ危険か

現行作の取り込み（`POST /api/scores/upload`）は「ベスト更新のみ書き換える」upsert なので、前作の高いスコアを一度入れると
新作の低い記録が全部無視される。ランキングは履歴の最新行を見るため、1 人でも入ると全ランキングの 1 位になる。

## 判定（`controller/StaleUploadGuard`）

どちらかに当たれば 400 を返し、何も保存しない。切替前（現行作がまだ前作）は判定しない。

| 段 | 材料 | 条件 | code |
|---|---|---|---|
| 1 | 各レコードの `sourceVersion`（ブックマークレットが実行ページの URL `/game/2dx/NN/` から読む） | 現行作より小さい | `STALE_PAGE_VERSION` |
| 2 | 公式 CSV の「最終プレー日時」（`lastPlayTime`）と `score` | 切替日時以降の譜面が 0 件、かつ切替前の日時でスコア > 0 の譜面が閾値以上 | `STALE_VERSION_DATA` |

- 新作では切替前にプレーした譜面のスコアは必ず 0 なので、正常な新作 CSV は段 2 に当たらない。
  新曲を 1 曲も遊んでいない人の CSV は全譜面スコア 0 で通り、稼働初日に遊んだ人の CSV は切替以降の日時が付くので通る。
- INFINITAS 由来のレコードと、最終プレー日時も作品番号も無い旧クライアントの送信は判定材料が無いので通す。
- 閾値は `app.version-transition.stale-upload-min-scored`（環境変数 `APP_VERSION_TRANSITION_STALE_UPLOAD_MIN_SCORED`、既定 5）。
- 切替日時は `IidxVersions.switchAt()`（`app.version-transition.launch-at`）。

レスポンス例:

```json
{ "message": "前作（Sparkle Shower）のスコアデータのようです。最終プレー日時が切替（2026/09/16 07:00）より前でスコアのある譜面が 20 件、切替以降にプレーした譜面が 0 件でした。…",
  "code": "STALE_VERSION_DATA", "staleScoredCount": 20, "freshCount": 0 }
```

## フロント側

- `utils/eagateScraper.ts` の `detectPageVersion()` が URL から作品番号を読み、`ScrapeResult.pageVersion` に載せる。
- ブックマークレット（`utils/mainBookmarklet.ts` → `/bookmarklet.js`）は取得前に `CURRENT_VERSION` と比べ、前作のページなら
  赤いバーで案内して止める。ブックマーク自体は `/bookmarklet.js` を読み込むだけなので、デプロイで全員に届く。
- `UnifiedImport.vue` → `App.vue` → `composables/useScoreUpload.ts` が `pageVersion` を各レコードの `sourceVersion` として送る。
- `useScoreUpload.upload()` はサーバーの 400 をその文言のまま `rejected = true` の Error にし、`App.vue` は理由を表示して
  取り込みを終える（「保存されなかった」扱いのフォールバックには進まない）。

## テスト

- `StaleUploadGuardTest`（判定の単体テスト 11 件）
- ローカル H2 での通し試験（前作 CSV → 400、稼働初日 CSV → 200、全譜面 0 → 200、前作ページのブックマークレット → 400、
  現行作ページ → 200、旧クライアント → 200、閾値未満 → 200）を 2026-09-16 に実施。

## 次回作への引き継ぎ

`IidxVersions.NEXT / PREVIOUS` と `iidxVersions.ts` の `NEXT_VERSION / PREVIOUS_VERSION / VERSION_SWITCH_AT` を更新すれば、
判定はそのまま次の切替でも働く。
