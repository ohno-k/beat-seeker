## 3. バックエンド詳細設計

### 3.1 BackendApplication / DataInitializer

```java
@SpringBootApplication
@EnableAsync
@EnableScheduling
public class BackendApplication { ... }
```

**DataInitializer（起動時処理、`CommandLineRunner`）**
1. `users.language IS NULL` を 'ja' に更新
2. `users.show_rate_tier IS NULL` を TRUE に更新
3. `song_definitions` が空なら `resources/data/song_data.json` を seed
4. `difficulty_ranks` が空なら `resources/data/difficulty_table.json` を seed

### 3.2 config レイヤー

#### SecurityConfig

```java
SecurityFilterChain filterChain(HttpSecurity http) {
  http.cors().and().csrf().disable()
      .sessionManagement().sessionCreationPolicy(STATELESS).and()
      .authorizeHttpRequests(auth -> auth
        .requestMatchers("/api/auth/register", "/api/auth/login",
                         "/api/auth/forgot-password", "/api/auth/reset-password",
                         "/api/game-data/**", "/api/scores/ranking*",
                         "/api/scores/rate-ranking*", "/api/scores/precision-ranking",
                         "/api/scores/song-*", "/api/scores/all-user-scores",
                         "/api/scores/debug-*", "/api/activity/feed",
                         "/api/tier-votes/all", "/api/tier-comments*",
                         "/api/votes", "/api/kofi/webhook",
                         "/api/analysis/**",
                         "/api/users/*/profile", "/api/users/*/scores",
                         "/api/users/*/history").permitAll()
        .requestMatchers("/api/admin/**").authenticated()  // 追加で userId==18 検証
        .anyRequest().authenticated())
      .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);
  return http.build();
}
```

- CORS: `${FRONTEND_URL}`, `http://localhost:5173`、`Access-Control-Allow-Credentials: true`
- パスワードは `BCryptPasswordEncoder`

#### JwtUtil

```java
String generateToken(String iidxId);           // HS256, exp=${jwt.expiration-ms}
String getIidxIdFromToken(String token);       // subject
boolean validateToken(String token);           // 署名・有効期限
```

#### JwtAuthFilter

```java
doFilterInternal:
  header = req.getHeader("Authorization")
  if header startsWith "Bearer " then
    token = header.substring(7)
    if jwtUtil.validateToken(token):
      iidxId = jwtUtil.getIidxIdFromToken(token)
      SecurityContext.setAuthentication(new UsernamePasswordAuthenticationToken(iidxId, null, emptyList()))
  chain.doFilter(...)
```

### 3.3 controller レイヤー

各コントローラは `@RestController + @RequestMapping` で構成。認証ユーザの解決は `SecurityContextHolder.getContext().getAuthentication().getName()` → `userRepository.findByIidxId(...)`。

管理者チェックは各 AdminController / Admin 系メソッドの冒頭で:
```java
User me = authUser();
if (me.getId() != 18L) throw new ResponseStatusException(FORBIDDEN);
```

### 3.4 service レイヤー

#### ScoreRecalculationService

- `@Async` で全ユーザーを反復し、`Score` から BEAT-PT / Rate-PT / Precision-PT を再計算し、最新 `ScoreHistoryLog` を更新、`User.totalBeatPt` にも反映
- ロジック: [`beatTier.ts`](../frontend/src/utils/beatTier.ts) と同仕様
- Rate-PT 補正: `patchZeroRatePtLogs` で `total_rate_pt = 0` レコードを現在スコアから補正

#### ChartTendencyService

- `chart_cache/profiles/` 配下の JSON を読み込み `ChartTendencyProfile` に UPSERT
- スコア予測（`predictScore`）: ユーザーの既プレイ曲の傾向ベクトルを既知の実スコアで回帰し、対象譜面の傾向ベクトルを入力して予測値を算出
- 類似度計算: 複数タグ・配置パターンの重み付きコサイン類似度
- `predictAllScores` は全曲の予測を返し、BEAT-Tier 算出に供給

#### SongRankBatchService

- `@Scheduled(cron=...)` で日次起動（または管理者から手動トリガー）
- 全ユーザー × ANOTHER/LEGGENDARIA 曲について、`RANK() OVER (PARTITION BY title, difficulty_name ORDER BY score DESC)` 相当の計算を行い `user_song_ranks` を洗い替え

#### PushNotificationService

- `webpush.WebPushService` ライブラリで `subscription` エンドポイントに POST
- VAPID 公開鍵・秘密鍵は `vapid.public-key / vapid.private-key` プロパティで注入
- 失敗時は 404/410 を検出して該当 `push_subscription` をクリア

#### EmailService

- `JavaMailSender` で Gmail SMTP へ送信
- テンプレート:
  - パスワードリセット: `${FRONTEND_URL}/reset-password?token=<UUID>`
  - 管理者通知（スコア更新 / サポーター認証）

#### TopRankersBeatPtService

- 外部 JSON（top-rankers-data）をもとにトップランカーのランキングを構築
- `getAreaProfile(versionNum, prefectureFileNum)` で地域プロフィール供給

#### SkillTreeService

- `ChartTendencyProfile` の類似度グラフを用いた推薦ツリー生成
- 未認証時はデフォルトツリー、認証時はユーザーの既スコア進捗を反映

#### GameDataService

```java
getActiveSongDataJson()          // revision=active の song_definitions を JSON 化
getActiveDifficultyTableJson()   // difficulty_ranks + difficulty_rank_songs を JSON 化
getDraftSongs()                  // revision=draft
addDraftSong(Map form)           // 複数難易度行を一括作成
deleteDraftSong(Long id)

hasDraftSongs() / hasDraftDifficultyTable()
seedSongData(...) / seedDifficultyTable(...)  // DataInitializer 用
```

## 4. API 仕様

下記に主要 API の入出力とステータスコードを整理する。全 API は JSON。認証が必要な API は `Authorization: Bearer <jwt>`。

### 4.1 認証系 `/api/auth`

#### POST `/api/auth/register`
```jsonc
// Request
{
  "iidxId": "1234-5678",
  "password": "xxxxx",
  "displayName": "DJ-NAME",
  "danRank": "皆伝",
  "arenaRank": "A1",
  "playSide": "1P",
  "email": "x@y.z"
}
// Response 200
{ "token": "<JWT>", "user": { /* public user */ } }
// Errors: 400 IIDX_ID_EXISTS / EMAIL_EXISTS
```

#### POST `/api/auth/login`
```jsonc
// Request
{ "iidxId": "1234-5678", "password": "xxxxx" }
// Response 200
{ "token": "<JWT>", "user": {...} }
// Errors: 401 Unauthorized
```

#### GET `/api/auth/me`（認証）
```jsonc
// Response 200 : 現在ユーザー情報（パスワード除く全カラム）
```

#### PUT `/api/auth/me/profile`（認証）
```jsonc
// Request（任意項目の部分更新）
{
  "displayName": "...",
  "danRank": "...",
  "arenaRank": "...",
  "playSide": "1P|2P",
  "privacyLevel": 0|1|2,
  "language": "ja|en|ko",
  "showRateTier": true,
  "showSupporterBorder": true,
  "email": "...",
  "currentPassword": "...",  // パスワード変更時
  "newPassword": "..."
}
// Response 200 { "user": {...} }
```

#### POST `/api/auth/forgot-password`
```jsonc
{ "iidxId": "1234-5678", "email": "x@y.z" }  // メール送信（存在有無にかかわらず 200）
```

#### POST `/api/auth/reset-password`
```jsonc
{ "token": "<uuid>", "newPassword": "..." }
// 1 時間有効。期限切れは 400。
```

### 4.2 スコア系 `/api/scores`

#### POST `/api/scores/upload`（認証）
```jsonc
// Request : フラット化されたスコア配列
[
  {
    "title": "...", "artist": "...", "genre": "...",
    "difficultyName": "ANOTHER", "difficultyLevel": 12,
    "score": 2345, "clearType": "HARD CLEAR", "djLevel": "AA",
    "pgreat": 1000, "great": 200, "missCount": 15, "playCount": 20
  }, ...
]
// Response 200
{
  "updatedCount": 37,
  "updatedSongs": [ { "title": "...", "difficulty": "...", "oldScore": ..., "newScore": ..., "oldClearType":..., "newClearType":... }, ... ],
  "message": "OK"
}
```
更新判定:
```
isImproved =
    newScore > oldScore ||
    clearTypeRank(new) > clearTypeRank(old) ||
    (newMissCount !=null && (oldMissCount==null || newMissCount < oldMissCount))
```
- フレンド被抜き検出 → `AppNotification(type=SCORE_BEAT)` + `PushNotificationService`

#### POST `/api/scores/save-history-log`（認証）
```jsonc
{
  "totalBeatPt": 17800.5,
  "beatPtIncrease": 32.1,
  "updatedCount": 5,
```

## 5. 認証・認可詳細

### 5.1 JWT

- アルゴリズム: HS256
- 有効期限: 7 日（既定 `jwt.expiration-ms=604800000`）
- Claim: `sub=iidxId`, `iat`, `exp`
- LocalStorage キー: `beat-seeker-token`
- 送信: `Authorization: Bearer <token>`

### 5.2 認可一覧

| 区分 | 判定 |
|------|------|
| 未認証 | `SecurityConfig.permitAll()` に該当 |
| 認証 | `JwtAuthFilter` で SecurityContext にセット |
| 管理者 | 認証済み かつ `userId == 18` |
| 所有者 | ルート毎（スコアメモ、ARENA 試合削除、コメント削除、Push 登録等） |
| プライバシー | `/api/users/{id}/*` 系は対象ユーザーの `privacyLevel==0`、または `friend-status` に応じて絞り込み |

### 5.3 パスワードリセット

1. `forgot-password`: `UUID.randomUUID()` → `password_reset_token`、`password_reset_expired_at = NOW + 1h`
2. Gmail SMTP で `${FRONTEND_URL}/reset-password?token=<uuid>` メール
3. `reset-password`: token 一致・期限内なら BCrypt で新パスワード設定

### 5.4 サポーター認証（Ko-fi）

1. ユーザー登録時に `supporter_token = "BS-" + 8桁英数` を UNIQUE で発行
2. Ko-fi 支援時に購入者が `supporter_token` をメッセージに記載
3. `/api/kofi/webhook?data=<url_encoded_json>` を受信
4. `verification_token` 照合 → `message` から `BS-XXXXXXXX` を正規表現で抽出
5. 該当 `users.is_supporter = TRUE`、管理者へメール

## 6. ビジネスロジック詳細

### 6.1 BEAT-PT 計算（`frontend/src/utils/beatTier.ts`、backend 側は Java で同仕様）

```ts
scoreRate = score / (notes * 2) * 100            // %
basePoints = (scoreRate / 100) ** 1.3 * weight

// ボーナス
bonus = 0
if (scoreRate > 77.77) bonus += 1
if (scoreRate > 88.88) bonus += 1
if (scoreRate > 94.44) bonus += 1
points = basePoints + bonus * weight / 100

// ウェイト
// informalRank = "11.0" → 150pt、"11.1" → 152pt、..., "12.4" → 178pt,
//               "12.5" → 182pt、以後 0.1 刻みで +3pt
// Uncategorized は 0pt（対象外）

totalBeatPt = sum( top 100 songs by points )
```

- ランク: 52 階層。Legend(18000), Mythic V〜I, ..., Silver, Bronze, Iron, Beginner
- 次ランクまでの進捗: `(current - prevThreshold) / (nextThreshold - prevThreshold) * 100`

### 6.2 Rate-PT

- 高精度帯に特化した倍増系列（25600 → 12800 → 6400 → 3200 → ...）でティア判定
- `showRateTier` が FALSE のユーザーはフロント表示を抑止

### 6.3 オプション投票の 1P 正規化

```
normalizeToFirstPlayer(optionType, myPlaySide):
  if myPlaySide == '2P' && optionType in ('REGULAR','MIRROR'):
    return optionType == 'REGULAR' ? 'MIRROR' : 'REGULAR'
  return optionType

convertToViewerPerspective(storedOption, viewerPlaySide):
  if viewerPlaySide == '2P' && storedOption in ('REGULAR','MIRROR'):
    return storedOption == 'REGULAR' ? 'MIRROR' : 'REGULAR'
  return storedOption
```
- RANDOM / R-RANDOM / S-RANDOM はスワップ対象外

### 6.4 スコアアップロードの差分処理

```
Map<(title, diffName, diffLevel), Score> existing = user.scores
for each inbound:
  key = (title, diffName, diffLevel)
  current = existing.get(key)
  if current == null:
    insert
  else if isImproved(current, inbound):
    update fields (score, clearType, djLevel, pgreat, great, missCount, playCount, uploadedAt)
user.lastUploadedAt = now()
return list of (title, diff, old*, new*)
```

- 改善判定は「スコア増」または「クリア強化」または「ミスカウント減」

### 6.5 ランクアップ検出（history-log 保存）

- フロントが `tierName` と `prevTierName` を送信
- 不一致なら `ActivityLog(RANK_UP)` を作り、全フレンドに通知

### 6.6 フレンド通知（被抜き）

```
notifyFriendsOfScoreBeat(uploader, updatedScores):
  if uploader.privacyLevel == 2: return
  friends = friendshipRepository.findByUser(uploader).map(f -> f.friend)
  for each updatedScore in updatedScores:
    for each friend in friends:
      friendScore = scoreRepository.findByUserAndTitleAndDifficulty(...)
      if friendScore != null
         && oldScore(uploader) < friendScore.score
         && newScore(uploader) > friendScore.score:
        notification = new AppNotification(friend, SCORE_BEAT, message)
        appNotificationRepository.save(notification)
        if friend.pushSubscription != null:
          pushNotificationService.sendNotification(...)
```

### 6.7 曲別順位キャッシュ更新

- ANOTHER / LEGGENDARIA 譜面のみ対象
- `RANK() OVER (PARTITION BY title, diff ORDER BY score DESC)` 相当を Spring Data / ネイティブ SQL で実装
- `user_song_ranks` をトランザクション内で TRUNCATE & INSERT

### 8.1 `utils/csvParser.ts`

```ts
parseScoreCsv(file: File): Promise<ScoreData[]>
```
- 文字コード: Shift_JIS（`iconv-lite`）

### 8.2 `utils/scoreData.ts`

```ts
flattenScores(scores: ScoreData[]): ScoreRecord[]

```
- `song_data.json` から `notes` を引き、`maxScore = notes * 2`
- `difficulty_table.json` から `informalRank` を解決
- BEAT-PT / Rate-PT を各譜面ごとに計算

### 8.3 `utils/beatTier.ts`

- RANK 定義（52 階層）、`getRankInfo(total)`, `getNextRankInfo(total)`
- 単曲ポイント計算、フォルダランクユーティリティ（`getFolderLegendRate`, `getLegendPtPerSong`）
- Rate-Tier 別ランクテーブル

### 8.4 `utils/bookmarklet.ts`

- eagate で動作する IIFE コード（minify 済み）を定数で保持
- ARENA バトル履歴＋スコア CSV を収集し、Base64 化して `#data=<base64>` を付与して beat-seeker にリダイレクト
- サイズ制限（>50KB で CSV を除外）、クリップボード経由フォールバック

## 10. 外部連携詳細

### 10.1 Gmail SMTP

- `spring.mail.host=smtp.gmail.com`、`port=587`、`properties.mail.smtp.starttls.enable=true`
- 送信種別
  - **パスワードリセット**: `${FRONTEND_URL}/reset-password?token=<UUID>`
  - **管理者通知**: スコア更新時の差分サマリ、サポーター認証通知

### 10.2 Web Push (VAPID)

- 購読情報は `users.push_subscription` (TEXT, `{endpoint, keys:{p256dh, auth}}` の JSON)
- クライアントは Service Worker + `PushManager.subscribe({ applicationServerKey: vapidPublicKey })`
- サーバは `webpush.WebPushService` で送信。`UnauthorizedRegistrationException`（404/410）を検出したら購読を NULL クリア

### 10.3 Ko-fi Webhook

```
POST /api/kofi/webhook
Content-Type: application/x-www-form-urlencoded
Body: data=<url_encoded_json>
```
- JSON は `{verification_token, message, from_name, amount, ...}`
- 検証: `body.verification_token == env.KOFI_VERIFICATION_TOKEN`
- トークン抽出: `message` から `\bBS-[A-Z0-9]{8}\b` を正規表現で抜き出し `supporter_token` でルックアップ
- ヒット時 `is_supporter = true` + 管理者通知メール

### 10.4 Textage

- 譜面表示サイトへの外部リンク（アプリからは静的 URL のみ）

## 11. エラー設計

### 11.1 HTTP ステータス方針

| シナリオ | ステータス |
|---|---|
| 入力バリデーション違反 | 400 Bad Request |
| 未認証 / 認証失敗 | 401 Unauthorized |
| 権限不足（管理者専用、他人のリソース操作） | 403 Forbidden |
| リソース未発見 | 404 Not Found |
| UNIQUE 競合 | 409 Conflict（ユーザー登録時の iidxId/email 重複など） |
| 内部エラー | 500 Internal Server Error |

### 11.2 バリデーション

- Bean Validation（`@Valid`, `@NotBlank`, `@Size`）を DTO に付与（RegisterRequest, ProfileUpdateRequest, SaveHistoryLogRequest, etc.）
- コメントは `@Size(max=1000)`、`privacyLevel` は 0/1/2 のみ許容など手動チェックあり

### 11.3 クライアント側

- `useAuth` / `useScores` / `useFriends` は `try/catch` で例外を握り、`console.error` と UI 通知（トースト）
- ネットワーク失敗時はリトライせず、ユーザーに再実行を促す（アップロードは冪等）

### 11.4 非同期処理のエラー

- `@Async` タスクは try/catch + ログ出力。上位に伝播しない
- Push 送信の失敗は個別ログ、全体処理は継続


- `docker-compose.yml` で backend / frontend / postgres を構成

1. `npm run build` → `dist/` に最新アセット＋`public/version.json` を生成

4. バックエンドは再起動で反映。ゲームデータ更新はドラフト → apply の流れ

- PostgreSQL 日次ダンプ（運用側のスケジュール）

### 12.5 モニタリング

- `backend_logs.txt` ほか、デバッグ用スナップショットが多数リポジトリ直下に存在（開発時の検証資料）

## 付録 A. 主要シーケンス図（テキスト）

### A.1 スコアアップロード

```
ユーザー → (ブックマークレット or CSV) → FE: App.vue
FE → POST /api/scores/upload [JWT] → BE: ScoreController.uploadScores
BE → ScoreRepository: 既存スコア取得（map化）
BE → 各スコアを isImproved 判定
BE → UPSERT 実行 + notifyFriendsOfScoreBeat
BE → AppNotificationRepository.save(...) + PushNotificationService.sendNotification
BE → Response { updatedCount, updatedSongs }
FE → UploadResultModal 表示 + BEAT/Rate-PT 再計算
FE → POST /api/scores/save-history-log
BE → ScoreHistoryLog 保存（ランクアップなら ActivityLog＋通知）
```

### A.2 ログイン

```
FE LoginModal → POST /api/auth/login → BE AuthController
BE → UserRepository.findByIidxId → BCrypt.matches
BE → JwtUtil.generateToken → Response { token, user }
FE → LocalStorage.setItem('beat-seeker-token', token)
FE → fetchCurrentUser / fetchGameData 等の初期化
```

### A.3 ゲームデータ更新適用

```
Admin → AdminGameDataModal でドラフト編集
Admin → POST /api/admin/game-data/apply
BE → GameDataService.applyDraft（revision を active にスワップ）
BE → ScoreRecalculationService.recalculateAllUsersAsync (@Async)
BE → 全ユーザーの履歴ログ・users.total_beat_pt を更新
BE → SongRankBatchService.recalculateAllAsync
BE → Response 202 Accepted
```
