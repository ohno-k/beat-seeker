# 単曲ティアの較正手順

`frontend/src/utils/beatTier.ts` の `BLOCK_BOUND_RATES`（☆ × 11 ブロック境界の必要 score rate）を
実データから引き直すための手順。作品が切り替わって難易度表を改訂したあと、
新作のスコアが十分たまった時点で実施する。

## 1. この表が何を決めているか

単曲ティアは「☆ × score rate → ティア名」の 2 次元の表で決まる。譜面固有の補正は入れない。

- **列**: 非公式難易度 ☆11.0 〜 ☆13.1（0.1 刻み、22 帯）
- **行**: Legend + 10 ブロック × 5 サブティア = 51 ティア。届かなければ Beginner
- **持っている値**: ブロック境界 11 本だけ。ブロック内の 5 サブティアは境界間をレート空間で 5 等分して作る

各境界の意味は次のとおり。

| 境界 | 決め方 | 意味 |
|---|---|---|
| Legend | その☆に属する譜面の **歴代全国レコード rate の p10** | 人類最高の水準。beat-seeker の分布から独立した外部基準 |
| Mythic 1 | 譜面ごとの「上位 1.2%」の rate → ☆内の中央値 | 以下すべて beat-seeker 内での順位 |
| Ancient 1 | 同 3.8% | |
| Master 1 | 同 8.0% | |
| Elite 1 | 同 13.5% | |
| Commander 1 | 同 20.5% | |
| Veteran 1 | 同 28.5% | |
| Expert 1 | 同 37.5% | |
| Advanced 1 | 同 47.5% | |
| Intermediate 1 | 同 60.0% | |
| Novice 1 | 同 80.0% | ここに届かなければ Beginner |

Legend だけ外部基準にしているのは、パーセンタイルで決めると「登録者の 1 位」が Legend になってしまい、
本来の「歴代レコード級」という意味が失われるため。逆に Legend まで歴代基準で通すと、
歴代レコードがその☆の平均より低い譜面で「人類未到達の Legend」が生まれる。
p10 はその妥協点で、2026-09 時点では歴代全国レコードの 89.5% がこの線を超え、
未到達は 1,192 譜面中 126 譜面（10.6%）。

## 2. 較正元のデータ

| 何を | どこから |
|---|---|
| スコア | 本番 DB の `past_scores`（前作の最終スコア）。`scores`（現行作）でも可 |
| ☆の所属 | `difficulty_ranks` / `difficulty_rank_songs` の **`revision = 'active'`** |
| 譜面の総ノーツ | `song_definitions`（`revision = 'active'`、`difficulty` は 4=ANOTHER / 10=LEGGENDARIA） |
| 歴代全国レコード | `backend/src/main/resources/top-rankers-data/0/00_全国.csv.gz` |

**☆の所属は必ず `active` を使う**。前作の凍結表（`archive:<version>`）で較正すると、
難易度改訂で移動した譜面が古い帯に残ったまま集計され、上位帯で score rate の逆転が起きる。
実際 2026-09 の較正では、`archive:33` 基準だと☆12.9 に皿曲が固まって☆13.0 より
中央 score rate が高くなり、☆12.9 だけ 2 倍以上厳しいティアになっていた。

## 3. 手順

### 3-1. 譜面ごとのパーセンタイルを取る

本番 DB に対して、譜面 1 つにつき目標パーセンタイル 10 点の EX スコアを直接取る。

```sql
WITH tbl AS (
  SELECT CASE WHEN btrim(drs.song_title) LIKE '%[L]'
              THEN btrim(left(btrim(drs.song_title), length(btrim(drs.song_title))-3))
              ELSE btrim(drs.song_title) END AS title,
         CASE WHEN btrim(drs.song_title) LIKE '%[L]' THEN 'LEGGENDARIA' ELSE 'ANOTHER' END AS difficulty_name,
         dr.rank_value
  FROM difficulty_rank_songs drs
  JOIN difficulty_ranks dr ON dr.id = drs.difficulty_rank_id
  WHERE dr.revision = 'active' AND dr.rank_value ~ '^[0-9]'
),
notes AS (
  SELECT title,
         CASE difficulty WHEN '4' THEN 'ANOTHER' WHEN '10' THEN 'LEGGENDARIA' END AS difficulty_name,
         notes
  FROM song_definitions
  WHERE revision = 'active' AND difficulty IN ('4','10') AND notes > 0
),
best AS (  -- 1 人 1 譜面 1 行（アーケード/INFINITAS の二重計上を潰す）
  SELECT ps.title, ps.difficulty_name, ps.user_id, MAX(ps.score) AS score
  FROM past_scores ps
  JOIN tbl t ON t.title = ps.title AND t.difficulty_name = ps.difficulty_name
  WHERE ps.version = 33 AND ps.score > 0
  GROUP BY ps.title, ps.difficulty_name, ps.user_id
)
SELECT t.rank_value, b.title, b.difficulty_name, n.notes, COUNT(*)::int AS total,
       MAX(b.score) AS top_score,
       percentile_disc(0.012) WITHIN GROUP (ORDER BY b.score DESC) AS q_mythic1,
       percentile_disc(0.038) WITHIN GROUP (ORDER BY b.score DESC) AS q_ancient1,
       percentile_disc(0.080) WITHIN GROUP (ORDER BY b.score DESC) AS q_master1,
       percentile_disc(0.135) WITHIN GROUP (ORDER BY b.score DESC) AS q_elite1,
       percentile_disc(0.205) WITHIN GROUP (ORDER BY b.score DESC) AS q_commander1,
       percentile_disc(0.285) WITHIN GROUP (ORDER BY b.score DESC) AS q_veteran1,
       percentile_disc(0.375) WITHIN GROUP (ORDER BY b.score DESC) AS q_expert1,
       percentile_disc(0.475) WITHIN GROUP (ORDER BY b.score DESC) AS q_advanced1,
       percentile_disc(0.600) WITHIN GROUP (ORDER BY b.score DESC) AS q_intermediate1,
       percentile_disc(0.800) WITHIN GROUP (ORDER BY b.score DESC) AS q_novice1
FROM best b
JOIN tbl t   ON t.title = b.title AND t.difficulty_name = b.difficulty_name
JOIN notes n ON n.title = b.title AND n.difficulty_name = b.difficulty_name
GROUP BY t.rank_value, b.title, b.difficulty_name, n.notes;
```

`percentile_disc(q) WITHIN GROUP (ORDER BY score DESC)` は「上位 q% の位置のスコア」。
score rate へは `score * 100 / (notes * 2)` で直す。
本番 DB へは `application-prod-db.yml` の接続情報で Node + `pg` から直接引く
（1,315 譜面 / 約 60 秒）。全レコードを引き上げるより桁違いに速い。

### 3-2. ☆ごとに中央値を取る

- Mythic 1 以下の 10 本: その☆に属する譜面の同じパーセンタイル rate の**中央値**
- Legend: その☆に属する譜面の歴代全国レコード rate の **p10**

譜面横断の中央値を使うのは、参加者数が譜面ごとに違う（中央 452 人、最大 1,007 人）ため、
レコードを混ぜて集計すると人気譜面に引っ張られるから。

### 3-3. ☆方向に単調化する

境界 11 本それぞれについて、☆が上がるほど値が下がるという制約を
**重み付き PAVA（Pool Adjacent Violators、重み = その☆の譜面数）** で満たす。
違反が数箇所しか出ないのが正常。大量に出たら難易度表の付け方を疑う。

2026-09 の較正では 11 本 × 21 遷移のうち違反は 3 箇所だけで、
実際に値が動いたのは Novice 1 の ☆13.0 / 13.1（64.37 / 65.77 → 64.99）のみだった。
☆13.0 に皿曲（灼熱 Beach Side Bunny、SAMURAI-Scramble[L]）が入っていて下位層が大きく落ちるのが原因。

### 3-4. 検算する

1. **境界が目標パーセンタイルを切っているか**: 全☆で 1.2 / 3.8 / 8.0 / … / 80.0% にほぼ一致すること
2. **単調性**: 52 ティア × 22 帯で、縦（ティアが下がる）も横（☆が上がる）も逆転が 0 件
3. **実レコードの分布**: Legend 約 0.12% / Ancient 以上 約 4.1% / Beginner 約 20%
4. **外部基準**: 歴代全国レコード → Legend、歴代の県トップ中央値 → Ancient 2、
   beat-seeker の譜面 1 位 → Mythic 5 あたりに落ちること

### 3-5. 表を差し替える

`beatTier.ts` の `BLOCK_BOUND_RATES` を書き換えるだけ。計算式も `FOLDER_RANK_DEFS` も触らない。
値は小数第 2 位まで（EX スコアに直すと 0.01% ≒ 0.2 点なので、これ以上の桁は意味がない）。

## 4. この方式の限界

**低☆では上位帯に物理的な幅がない。** ☆11.0 では 1 位と上位 1% の差が EX 2.2 点しかなく、
そこに Legend + Mythic 5 段を並べると 1 ティアあたり 0.4 点になる。
☆12.8 の 42.0 点と比べて 19 倍の差があり、これは表の引き方では解けない。
上位帯のサブティアを☆に応じて畳むなら、ここが判断の起点になる。

**母集団は beat-seeker 登録者。** 申告段位は皆伝 65.5% / 中伝 14.4% で、IIDX 全国の分布ではない。
「上位 80%」は *beat-seeker の中で* の話なので、一般のプレイヤーにとっては実際より厳しい線になる。

**☆12.9 以上は譜面が少ない。** 2026-09 時点で 12 / 5 / 4 譜面。
新曲がこの帯に入ることは多くないので当面は作り直さなくてよいが、
難易度表を改訂して所属が動いたら引き直すこと。
